# ADR-002: Utilizar GitHub Actions para CI/CD do workflow


## Contexto

O workflow de automação da VendeMais precisa ser versionado e possuir um processo controlado de atualização.

O blueprint do Make pode ser armazenado no GitHub, porém alterações realizadas diretamente no ambiente do Make podem não estar refletidas no repositório.

Também existe a necessidade de reduzir alterações manuais e aumentar a rastreabilidade das mudanças.

## Decisão

Será utilizado o **GitHub Actions** como mecanismo de CI/CD do projeto.

O processo será baseado na branch `main`. Alterações no workflow armazenado no GitHub deverão passar pelas validações automatizadas existentes antes de serem consideradas prontas para sincronização com o ambiente de automação.

As credenciais e chaves de API não serão armazenadas no código. Quando necessário, serão utilizadas variáveis e secrets do GitHub Actions.

O workflow principal continuará sendo executado pelo Make.com. O GitHub Actions será responsável pelo processo de validação, versionamento e futura sincronização controlada do blueprint.

## Alternativas consideradas

### Atualização manual pelo Make.com

Seria possível realizar alterações diretamente no Make e posteriormente atualizar o arquivo no GitHub.

Essa abordagem exige mais ações manuais e dificulta a rastreabilidade das alterações.

### Outro serviço de CI/CD

Poderiam ser utilizados outros serviços de integração e entrega contínuas.

Entretanto, o GitHub Actions foi escolhido por estar integrado ao próprio repositório utilizado pelo projeto, evitando a necessidade de adicionar outra plataforma.

## Consequências

### Positivas

- Centralização do código e da automação no GitHub.
- Validação automática dos workflows.
- Maior rastreabilidade das alterações.
- Redução de alterações manuais.
- Possibilidade de sincronização automatizada com o Make.
- Uso de secrets para proteger credenciais.

### Negativas

- Será necessário configurar os secrets e workflows do GitHub Actions.
- A integração com a API do Make precisará ser configurada posteriormente.
- Alterações feitas diretamente no Make precisarão ser controladas para evitar divergências em relação ao GitHub.

## Próximos passos

1. Criar o workflow do GitHub Actions.
2. Executar os testes existentes automaticamente.
3. Configurar os secrets necessários.
4. Implementar a sincronização do blueprint com o Make.
5. Criar um mecanismo para identificar alterações realizadas diretamente no Make.
